009                                                    A BSTRACT
010
011
               Large language model (LLM)-based multi-agent systems have shown strong capabilities in
012
               tasks such as code generation and collaborative reasoning. However, the effectiveness and
013            robustness of these systems critically depend on their communication topology, which is
014            often fixed or statically learned, ignoring real-world dynamics such as model upgrades, API
015            (or tool) changes, or knowledge source variability. To address this limitation, we propose
016            CARD (Conditional Agentic Graph Designer), a conditional graph-generation framework
017            that instantiates AMACP, a protocol for adaptive multi-agent communication. CARD
018            explicitly incorporates dynamic environmental signals into graph construction, enabling
019            topology adaptation at both training and runtime. Through a conditional variational graph
020            encoder and environment-aware optimization, CARD produces communication structures
021
               that are both effective and resilient to shifts in model capability or resource availability.
               Empirical results on HumanEval, MATH, and MMLU demonstrate that CARD consistently
022
               outperforms static and prompt-based baselines, achieving higher accuracy and robustness
023
               across diverse conditions. The source code is available at: https://anonymous.
024            4open.science/r/agentgraph-FF9A.

028   1    I NTRODUCTION
029
030   Multi-agent systems powered by large language models (LLMs) (OpenAI, 2024a; Liu et al., 2023a) have
031   recently demonstrated remarkable capabilities across a wide range of complex tasks, from code synthe-
032   sis (Chen et al., 2023) to collaborative reasoning (Liu et al., 2023b). By integrating each model’s internal
033
      knowledge, natural language generation, and inference abilities with external tools (Zhang et al., 2023) or peer
      LLMs, these systems effectively decompose problems (Yao et al., 2023a), coordinate subgoals (Liang et al.,
034
      2023), and integrate diverse information sources (Lee et al., 2023). However, the communication topology,
035
      which specifies how agents are interconnected, significantly influences performance, affecting both solution
036   quality and robustness to evolving conditions such as model upgrades, API modifications, and fluctuating
037   data sources.
038
039
      Current topology design approaches typically fall into two categories (Bei et al., 2025; Liu et al., 2025). Many
      systems depend on manually crafted pipelines (Hong et al., 2023) or predefined agent sequences (Wu et al.,
040
      2023), which perform effectively in stable, well-understood scenarios but lack adaptability. Conversely, recent
041
      methods automatically learn communication structures by backpropagating through "text gradients" (Zhuge
042   et al., 2024) or parameterizing inter-agent connections via differentiable modules (Zhang et al., 2025a).
043   Yet, these learned topologies generally assume static environments, failing to account for transient external
044   factors. Consequently, when conditions change, such as upgrading a model base (e.g. GPT-4o → GPT-5),
045   tool availability variations, or deterioration in data source quality, static or naively learned topologies become
046   fragile, resulting in redundant interactions or disrupted information flows (see Figure 1).

067
         Adaptive LLM-based Multi-agent Communication Protocol (AMACP):
068
069
         Given a task/query q, an optimal communication topology for q should satisfy the following protocol
070
         logics: Effectiveness: The communication structure must effectively produce a qualified solution for
071      the given task q. Cost-efficiency: The communication structure should minimize the overall resource
072      consumption (e.g., model usage, API calls, token cost) required to solve q under the given condition.
073      Adaptiveness: The communication structure should dynamically adjust to varying conditions, ensuring
074      robustness across diverse availability.
075
076   We address this gap by formalizing the Adaptive Multi-Agent Communication Protocol (AMACP) and
077   instantiating it via the Conditional Agentic gRaph Designer (CARD). CARD is a conditional graph-generation
078   framework that (i) represents each agent via profile and condition channels, (ii) encodes dynamic environment
079   signals, and (iii) decodes an interaction graph whose edges adapt at training time and at runtime as conditions
080   change without retraining. The objective balances task utility and condition-aware communication cost,
081   enforcing effectiveness, cost-efficiency, and adaptiveness required by AMACP. Empirically, on H UMAN E VAL,
082   MATH, and MMLU with simulated environmental changes (model upgrades, tool availability, data-source
083   perturbations), CARD yields substantial gains over static and prompt-only or naively learned topologies
084
      while remaining competitive in static regimes. Our primary contributions are:
085
             • Formalization of AMACP, a protocol enabling adaptive multi-agent communication under dynamic
086
               external conditions.
087
088
             • Introduction of CARD, a conditional graph-generation framework explicitly learning effective and
               adaptive agent topologies from environmental states.
089
090          • Comprehensive empirical validation demonstrating that CARD consistently outperforms existing
091            fixed and learned topology baselines under dynamic conditions.
092          • Detailed analyses of topology adaptations, elucidating how environmental state conditioning en-
093            hances the efficiency and robustness of multi-agent coordination.

      2     R ELATED W ORK
095
096
      Collaborative LLM Agents. Early work on LLM-based multi-agent communication has relied on manually
097   defined coordination pipelines, with ranging from non-interactive queries and chain-of-thought prompting to
098   debate frameworks and fixed tree- or graph-based structures (Wei et al., 2022b; Yao et al., 2023b; Besta et al.,
099   2024). To reduce the effort of handcrafting these pipelines, automated topology-learning methods such as
100   GPT-Swarm (Zhuge et al., 2024), G-Designer (Zhang et al., 2025a), and Aflow (Zhang et al., 2025b) have
101   been developed. These approaches optimize agent connections via differentiable modules or heuristic search,
102   yielding strong performance in static settings. However, they continue to assume a stationary environment
103   and lack mechanisms for responding to changes in model capabilities, tool access, or data quality.
104
105   Multi-Agents as Graphs. Although a few dynamic communication protocols have been proposed in
106   distributed-systems literature (Wei et al., 2022a; Yao et al., 2023a; Liang et al., 2023), most learned topologies
107
      remain static and brittle under evolving conditions, such as model upgrades, fluctuations in external tool
      reliability, or shifts in data-source quality (Pareja et al., 2020; Chang et al., 2020). In these scenarios, pre-
108
      defined or naively optimized graphs can produce redundant interactions or disrupted information flows (Liu
109
      et al., 2025). To bridge this gap, we introduce the Conditional Agentic Graph Designer, which explicitly
110   conditions graph generation on external signals (e.g., model version, tool performance, data-source fidelity)
111   to produce adaptive, robust multi-agent topologies .

      We begin by formalizing the topology and protocol design space for LLM-based multi-agent systems (MAS),
116
      grounding the CARD framework (Figure 2) in well-defined constructs.

118
      Topological Structure of LLM-based Multi-Agent Systems. A multi-agent system is represented as
119   a directed graph G = (V, E), where each node vi ∈ V denotes an LLM-based agent and each directed
120   edge (vi , vj ) ∈ E represents a communication path from vi to vj . Each agent vi is described by: profile
121   attributes Pi , including [role identity, model base, tool access, historical state];
122   And condition attributes Ci , capturing runtime environmental conditions. We model the condition C as a
123   composition of multiple features, where each feature corresponds to a distinct semantic aspect F such as
124   model type, tool availability, or task complexity. Formally,
125                                          C = {c1 , c2 , . . . , ck }, ci ∈ Fi ,                                 (1)
126
                                             C = F1 × F2 × · · · × Fk ,                                             (2)
127
128   To ensure semantic consistency across heterogeneous features, we encode the structured condition using a
129
      unified pretrained language model, aligning all feature dimensions into a shared embedding space, enabling
      the model to handle unseen combinations of features during inference.

201   4    C ONDITIONAL AGENTIC G RAPH D ESIGNER
202
203   We introduce Conditional Agentic Graph Designer (CARD) that constructs adaptive, environment-conditioned
204   multi-agent topologies. CARD comprises four key stages: (1) Agent representation, (2) Conditional graph gen-
205   eration, (3) Environment-aware training, and (4) Runtime adaptation. The complete workflow is summarized
206
      in Algorithm 1 and visualized in Figure 2.
207
208   Agent Representation. Given a query Q and an environment configuration C, CARD first constructs an
209   initial multi-agent network. Each agent vi ∈ V is described by two components: Firstly, a profile vector
210
      Pi = [Tp (Basei ), Rolei , Tp (Plugini )], capturing static attributes of the agent, including its base model,
      assigned role, and supported tools. Here, Tp (·) denotes a natural-language template function used to verbalize
211
      categorical features (e.g., model name, role identity, plugin type) into a text embedding. Secondly, a condition
212
      vector Ci = Tc (Ci ), describing runtime environment status for vi , such as model availability, token cost, or
213   API reliability. The function Tc (·) generates textual descriptions that encode dynamic system conditions.
214   These representations are later encoded as node features for conditional graph generation (Section 4). See
215   Appendix F for template instantiations of Tp and Tc .
216
217   Conditional Graph Generation Given a user query Q and an initial environment configuration, CARD
218   constructs a preliminary agent graph Ge = (V, E)e over N = |V| agents. Each agent vi ∈ V is associated with
219   a profile text Pi and a condition text Ci , which are embedded as Xip and Xic , respectively. Stacking across

      A     L IMITATION
612
613
      This work focuses on conditional optimization and adaptation of multi-agent communication topologies.
614
      However, it does not explicitly update agent-level configurations such as individual prompts or internal
615   profiles in response to environmental shifts. In practice, jointly optimizing both the communication topology
616   and agent behaviors, including prompt augmentation and tool selection strategies, may further improve
617   system performance. Exploring this direction remains an open avenue for future research. Additionally, while
618   our formulation represents the multi-agent system as a graph, which offers a cognitively interpretable and
619   analyzable abstraction, graph-based representations may be insufficient for capturing domain-specific nuances
620   in complex real-world settings. For example, in software engineering workflows, procedural constraints, tool
621   dependencies, and execution semantics are often critical. Future work may incorporate human-in-the-loop
622   expertise, such as software development best practices and debugging heuristics, and explore hybrid models
623
      that combine symbolic priors with learned agent adaptation mechanisms.

757   when the compromised node is restored (+3.33 pp vs. +1.24 pp on HumanEval; the accuracy under attack
758   is even higher than non-attacked on MATH, indicating that our topology is fully adaptable to both attacked
759   and non-attacked conditions.) highlighting its superior resilience and adaptability across both degraded and
760   recovered environments.

764
      Localized condition updates recover most of the lost performance at minimal adaptation cost. Figure 6
765
      (Right) illustrates that, upon replacing only a single node’s condition rather than regenerating the entire
766   communication graph, CARD retains 88.33 % accuracy under head-node perturbations and 85.00 % under
767   intermediate-node perturbations, demonstrating overall superiority over both LLM-Debate and G-Designer,
768   highlighting that fine-grained adaptation can preserve robustness with far lower computational overhead than
769   global reconfiguration.

773
774   Conditional designs deliver the best accuracy-to-cost balance among all methods. In Figure 8 (Right),
775
      CARD’s configurations (e.g., achieving 94 % accuracy at an evaluation cost of 4 × 10−3 USD) occupy the
      upper–left region of the cost–performance plane, while static multi-agent schemes like LLM-Debate and
776
      learned topologies such as G-Designer generally cost more to reach a lower accuracy; this confirms that
777
      conditionally adapted graphs not only boost resilience but also minimize economic expenditure for a given
778   performance level.
