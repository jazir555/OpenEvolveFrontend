# Z3 Behavioral Equivalence Verification for RESE Phase II

## Overview

This document describes the Z3-based behavioral equivalence verification system implemented for RESE Phase II (Isomorphic Mapping). The system enhances mechanistic isomorphism validation (I_mech) by replacing structural overlap heuristics with formal Z3 proofs of behavioral equivalence.

## Architecture

### Components

1. **CrossDomainMapper (Enhanced)**
   - Main orchestrator for isomorphism detection
   - Integrates Z3 verification into I_mech calculation
   - Falls back to structural-only mode when Z3 unavailable

2. **FDG Encoder**
   - Encodes Functional Dependency Graphs as SMT-LIB2 formulas
   - Maps nodes to Z3 variables (Bool, Int, Real)
   - Encodes edges as implications or equalities

3. **Equivalence Verifier**
   - Proves behavioral equivalence: ∀ inputs. behavior(source) ≡ behavior(target)
   - Uses Z3 theorem prover for formal verification
   - Optional Z3-LeanAide bridge for cross-validation

4. **Equivalence Result**
   - Data class containing verification results
   - Includes verification status, confidence, proof, counterexample

### Data Flow

```
Source FDG + Target FDG
         ↓
   Compute Structural Overlap
         ↓
   Structural Score > Threshold?
         ↓ Yes
   Encode FDGs to Z3 Formulas
         ↓
   Verify Behavioral Equivalence
         ↓
   Z3 Proof (Valid/Invalid)
         ↓
   Combine Structural + Behavioral Scores
         ↓
   Final I_mech Score
```

## Configuration

### Environment Variables

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `RESE_Z3_PHASE2_ENABLED` | bool | `true` | Enable Z3 behavioral verification |
| `RESE_Z3_USE_BRIDGE` | bool | `false` | Use Z3-LeanAide bridge for cross-validation |
| `Z3_TIMEOUT` | int | `10000` | Z3 solver timeout in milliseconds |
| `RESE_STRUCTURAL_WEIGHT` | float | `0.7` | Weight for structural score in I_mech |
| `RESE_BEHAVIORAL_WEIGHT` | float | `0.3` | Weight for behavioral score in I_mech |

## Usage

### Basic Usage

```python
from phase2_executor import CrossDomainMapper, Phase2Logger
from rese_schemas import Phase2Config, FunctionalDependencyGraph

# Create configuration
config = Phase2Config.from_env()

# Create mapper
logger = Phase2Logger(correlation_id="test-001")
mapper = CrossDomainMapper(config, logger)

# Compute I_mech score (with Z3 verification if enabled)
score = mapper.compute_imech_score(
    source_fdg=fdg1,
    target_fdg=fdg2,
    domain_knowledge=None,
    correlation_id="test-001"
)

print(f"I_mech score: {score:.3f}")
```

### Finding Isomorphic Mappings

```python
# Find mappings with Z3 verification
mappings = mapper.find_isomorphic_mappings(
    source_fdg=source_fdg,
    target_fdgs=[fdg1, fdg2, fdg3],
    correlation_id="test-002"
)

for mapping in mappings:
    print(f"{mapping.source_domain} -> {mapping.target_domain}")
    print(f"  I_mech: {mapping.i_mech_score:.3f}")
    print(f"  Type: {mapping.isomorphism_type}")
```

### Manual Behavioral Verification

```python
# Direct behavioral equivalence check
from phase2_executor import EquivalenceResult

result = mapper._verify_behavioral_equivalence(
    fdg1=source_fdg,
    fdg2=target_fdg,
    correlation_id="test-003"
)

if result.verified:
    print(f"Behaviorally equivalent! Confidence: {result.confidence:.2f}")
    print(f"Proof: {result.proof}")
else:
    print(f"Not equivalent")
    if result.counterexample:
        print(f"Counterexample: {result.counterexample}")
```

## FDG Encoding

### Variable Types

The encoder automatically selects variable types based on domain:

| Domain | Variable Type | Reason |
|--------|--------------|--------|
| `physics` | `Real` | Continuous quantities |
| `economics` | `Real` | Continuous values |
| `computer_science` | `Int` | Discrete values |
| `biology` | `Int` | Counts, populations |
| Other | `Bool` | Logical variables |

### Edge Encoding

Dependencies are encoded based on strength:

- **Strong (≥0.9)**: Equality `(= target source)`
- **Medium (≥0.5)**: Implication `(=> source target)`
- **Weak (<0.5)**: Ignored in formal proof

## Verification Strategies

### 1. Structural Only (Backward Compatible)

When Z3 is disabled or unavailable:

```bash
export RESE_Z3_PHASE2_ENABLED=false
```

I_mech = 0.7 × Structural Overlap + 0.3 × Size Ratio

### 2. Z3 Verification (Default)

When Z3 is enabled:

```bash
export RESE_Z3_PHASE2_ENABLED=true
export Z3_TIMEOUT=10000
```

I_mech = 0.7 × Structural Score + 0.3 × Behavioral Confidence

### 3. Z3 + LeanAide Bridge (Cross-Validation)

For highest confidence:

```bash
export RESE_Z3_PHASE2_ENABLED=true
export RESE_Z3_USE_BRIDGE=true
```

Both Z3 and LeanAide must agree for verification to pass.

### Optimization Tips

1. **Adjust Timeout**: Reduce `Z3_TIMEOUT` for faster failures
2. **Disable Bridge**: Set `RESE_Z3_USE_BRIDGE=false` to skip LeanAide
3. **Threshold Tuning**: Increase `i_mech_threshold` to skip Z3 more often
4. **Weight Adjustment**: Reduce `RESE_BEHAVIORAL_WEIGHT` to favor structural scores

## Troubleshooting

### Z3 Not Available

**Symptom**: Logs show "Z3 enabled but not available"

**Solution**: Install Z3:
```bash
# Python bindings
pip install z3-solver

# Or binary (for CLI fallback)
# Download from https://github.com/Z3Prover/z3/releases
```

### Timeouts

**Symptom**: "Z3 behavioral verification failed - using structural only"

**Solutions**:
- Increase `Z3_TIMEOUT` (default 10000ms)
- Simplify FDGs (fewer nodes/dependencies)
- Check for circular dependencies
- Reduce graph complexity before verification

### Encoding Errors

**Symptom**: "Failed to encode FDG to Z3"

**Solutions**:
- Check node names don't contain special characters
- Verify domain is one of: physics, economics, computer_science, biology
- Ensure dependencies have valid source/target references

### Import Errors

**Symptom**: "Cannot import Z3TheoremProver"

**Solutions**:
- Ensure `z3prover_integration.py` is in root directory
- Check Python path includes root directory
- Verify Z3 is installed

## API Reference

### CrossDomainMapper

#### `__init__(config, logger)`

Initialize mapper with Z3 support.

**Parameters**:
- `config`: Phase2Config instance
- `logger`: Phase2Logger instance

#### `compute_imech_score(source_fdg, target_fdg, domain_knowledge, correlation_id)`

Compute I_mech score with Z3 behavioral verification.

**Parameters**:
- `source_fdg`: Source FunctionalDependencyGraph
- `target_fdg`: Target FunctionalDependencyGraph
- `domain_knowledge`: Optional domain metadata (not currently used)
- `correlation_id`: Distributed tracing ID

**Returns**: `float` - I_mech score [0.0, 1.0]

#### `find_isomorphic_mappings(source_fdg, target_fdgs, correlation_id)`

Find isomorphic mappings between domains.

**Parameters**:
- `source_fdg`: Source FunctionalDependencyGraph
- `target_fdgs`: List of target FunctionalDependencyGraph
- `correlation_id`: Distributed tracing ID

**Returns**: `List[IsomorphicMapping]` - Sorted by I_mech score

### EquivalenceResult

Data class containing verification results.

**Attributes**:
- `verified`: bool - True if behaviorally equivalent
- `confidence`: float - Confidence score [0.0, 1.0]
- `proof`: Optional[str] - Z3 proof (if verified)
- `counterexample`: Optional[Dict] - Counterexample (if not verified)
- `solver`: str - Solver used ('z3', 'z3_leanaide_bridge', 'error')
- `execution_time`: float - Execution time in milliseconds
- `errors`: List[str] - Error messages

**Methods**:
- `to_dict()`: Convert to dictionary

## Design Principles

### CLAUDE.md Compliance

1. **Law of Air Gap**: Uses root-level `z3prover_integration.py` and `z3_leanaide_bridge.py`, no direct imports into core-projects

2. **Law of Runtime Truth**: Probes Z3 API before use, falls back gracefully if unavailable

3. **Law of Configuration Explicitness**: All configuration via environment variables, crashes on invalid config

4. **Circuit Breaker**: Timeout handling, fallback to structural-only on errors

5. **Structured Logging**: JSON logs with correlation_id, source_service, target_service

6. **Idempotency**: Same FDGs → same I_mech score (deterministic)

### Backward Compatibility

- Fully backward compatible: works with Z3 disabled
- Existing code continues to use structural overlap
- No breaking changes to API
- Graceful degradation on errors
